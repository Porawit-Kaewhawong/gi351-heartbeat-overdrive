# 01 — วิเคราะห์เกม Heartbeat Overdrive

## สรุปความเห็นภาพรวม

คอนเซปต์นี้ **เหมาะกับงาน 1 สัปดาห์มาก** และการตัดระบบ (Parry, Fever, Leaderboard ฯลฯ)
ที่ทีมตัดสินใจไว้เป็นการตัดที่ถูกต้องทั้งหมด เหตุผล:

- ปุ่มเดียว = อินพุตระบบเดียว ไม่มี edge case เยอะ เดโมง่าย กรรมการเข้าใจใน 10 วินาที
- จุดขายไม่ได้อยู่ที่ "ปริมาณระบบ" แต่อยู่ที่ **ความรู้สึก (game feel)** สองอย่างคือ
  Climax Shift กับ Redline ซึ่งทั้งคู่เป็นงาน "ปรับค่า + เอฟเฟกต์" ไม่ใช่งานระบบใหญ่
- เกมจบใน 1-2 นาที → เทสง่าย บาลานซ์ง่าย ทำเทรลเลอร์ง่าย

**ความเสี่ยงหลักของโปรเจกต์นี้ไม่ใช่ "ทำไม่ทัน" แต่คือ "ทำทันแต่ไม่มัน"**
เกมจังหวะที่ timing เพี้ยนแม้แค่ 50ms จะรู้สึกแย่ทันที ดังนั้นครึ่งแรกของสัปดาห์
ต้องทุ่มให้ความแม่นของจังหวะและน้ำหนักของฟีดแบ็ก ก่อนจะไปแต่งสวย

## จุดแข็งของดีไซน์

1. **Dynamic Pressure สองทิศทางสมมาตรกันสวยงาม** — ศัตรูเลือดน้อย = เกมเร็วขึ้น (กดดันด้วยกลไก),
   เราเลือดน้อย = ภาพ/เสียงรบกวน (กดดันด้วยจิตวิทยา) เป็น hook ที่เล่าได้ในประโยคเดียว
   และทำให้แมตช์ช่วงท้ายตึงเสมอไม่ว่าใครจะนำ
2. **Miss มีความหมาย** — ไม่ใช่แค่เสียคอมโบ แต่โดนสวนทันที ทำให้ทุกการกดมีเดิมพัน
3. **ขอบเขตงานอาร์ตยืดหยุ่น** — เกมเล่นได้ตั้งแต่ยังเป็นวงกลม placeholder
   อาร์ตที่เพิ่มเข้ามาคือ "ของแถมที่ยกระดับ" ไม่ใช่ "ของที่ต้องรอ" → ทีมไม่บล็อกกันเอง

## ความเสี่ยง และวิธีที่โค้ดชุดนี้จัดการให้แล้ว

| ความเสี่ยง | ผลถ้าพลาด | การจัดการ |
|---|---|---|
| Timing เพี้ยนตาม framerate | เกมจังหวะ "รู้สึกหลอก" ทันที | Conductor/PulseRing อิง `AudioSettings.dspTime` ไม่ใช่ `Time.time` |
| ผู้เล่นรัวปุ่มมั่วเพื่อฟลุค Perfect | เกมพัง ไม่ต้องมีฝีมือ | กดนอกหน้าต่างตัดสิน = Miss + มี input cooldown |
| Hit Freeze ทำจังหวะเคลื่อน | คอมโบหลุดแบบไม่แฟร์ | จังหวะอิง dspTime ซึ่งไม่หยุดตาม timeScale — freeze สั้น 0.05s จึงไม่กระทบการตัดสิน |
| จังหวะเร่งจนเป็นไปไม่ได้ | ช่วงท้ายเกมกลายเป็นสุ่ม | BPM คงที่ 90 ตลอด ความกดดันมาจากความถี่ของวงที่ไต่จาก 2.00 ลงไป 1.25 บีตต่อวง มีพื้นกันที่ `minBeatsPerPulse` |
| ซีน Unity merge conflict | เสียงานครึ่งวัน | ซีนสร้างจากสคริปต์ (Setup Menu) — พังก็กดสร้างใหม่ได้ + กติกาห้ามแก้ซีนพร้อมกัน |
| เพลงกับจังหวะเกมไม่ตรงกัน | ผู้เล่นจับจังหวะจากเพลงแล้วพลาด | ดีไซน์ให้ "จังหวะเกมเป็นตัวนำ" — เพลงเป็น backing ambience, ตัวชี้จังหวะจริงคือวง Pulse + เสียงติ๊กตามบีต (ดูหมายเหตุด้านล่าง) |

### หมายเหตุเรื่องเพลง (ตัดสินใจแล้ว ควรรู้ไว้ทั้งทีม)

เพราะ BPM ของเกม **เปลี่ยนตลอดเวลา** (Climax Shift) การจะให้เพลงเร่งตามแบบไร้รอยต่อ
ต้องใช้เทคนิค time-stretching ซึ่งเกินขอบเขต 1 สัปดาห์ ทางเลือกที่ใช้:

- ตัวนำจังหวะจริงของผู้เล่น = **ภาพวง Pulse + เสียงเคาะตามบีต** (ตรง 100% เสมอ)
- เพลงประกอบเป็นเลเยอร์บรรยากาศ ทำที่ ~90-100 BPM ให้กลมกลืนช่วงต้นเกม
- ถ้ามีเวลาเหลือ (stretch goal): ใช้ `musicSource.pitch` เร่งเพลงตาม BPM แบบหยาบๆ ได้ใน 1 ชม.

## แนวทางบาลานซ์เริ่มต้น (ตั้งไว้ใน GameConfig แล้ว)

- มอนสเตอร์ 3 ตัว 40 / 55 / 75 HP (รวม 170) / Perfect 7 (+โบนัสคอมโบสูงสุด +3) / Great 3
  → เล่นเก่งชนะใน ~14-17 ครั้ง (ราว 45-70 วินาที) กำลังพอดีเดโม
- ผู้เล่น 100 HP / Miss โดนสวน 10 → พลาดได้ ~9 ครั้ง ก่อนแพ้
- หน้าต่างตัดสิน: Perfect ±65ms / Great ±130ms (มาตรฐานเกมจังหวะสาย casual)
  ถ้าเทสแล้วยากไป ให้ขยาย Perfect เป็น ±80ms ก่อนอย่างอื่น
- Redline เริ่มที่ HP < 50% แล้วไต่ความเข้มถึงสุดที่ 0%

## สิ่งที่ควรตัดเพิ่ม ถ้าถึงวันพุธแล้วยังช้ากว่าแผน (เรียงตามลำดับที่ควรตัดก่อน)

1. โบนัสคอมโบ (เหลือ Perfect ดาเมจคงที่) — ตัดได้ใน 1 นาที แทบไม่มีใครสังเกต
2. อนิเมชันตัวละครหลายเฟรม — ใช้ 2 เฟรม (idle/hurt) + การพุ่งตัวจากโค้ดก็ดูดีพอ
3. เพลงประกอบ — เกมนี้อยู่ได้ด้วยเสียงเคาะบีต + SFX + เสียงหัวใจ
4. **ห้ามตัด:** ความแม่น timing, Redline, Climax Shift, ฟีดแบ็ก Perfect — นี่คือตัวเกม
